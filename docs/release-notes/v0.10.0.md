# CC Switch X v0.10.0

这一版收了四条使用反馈，外加一条真机才暴露的搬迁缺口。最重的一笔是**项目级 Skills 的真源与台账搬进客户端**：上一版把真源放进项目仓库，实际用起来就是一份和渲染目录重复、却从不参与跨机器协作的内容，每改一次 skill 都在 `git status` 里多一份噪音。

## 项目真源搬进客户端（v3 布局）

- 新布局：`<storeRoot>/local/projects/<project-id>/{skills/<id>/, skills.json, layout.json}`。项目里只剩 `.claude|.qoder|.agents/skills/` 这些渲染产物；`local/` 在 store 的 `.gitignore` 必需条目里，且备份采集是白名单，所以这份真源不进 Git 同步、也不进云备份。
- 台账 `version` **保持 2**：它只记目录内相对路径与目录 key，升版本会让 v1→v2 迁移器把所有项目误判成待迁移。布局改用独立的 `layout.json`（version 3），两条轴交叉表达「两边都有」的半状态。
- 存量项目自动搬迁：打开或添加项目时先整份快照进 `backups/projects/<id>/<ts>/legacy/`，逐 skill 复制并比对树哈希、台账回读反序列化，全部一致才写布局戳记；**只有「戳记已写 + 每个 skill 哈希一致 + 旧目录里没有陌生条目」三条同时成立才删除 `.ccswitchx/`**。删除失败不回收搬迁，只在报告里记一条 warning。
- 两边内容有分歧时判 `Hybrid`，面板顶部给「以客户端为准 / 以项目为准」两个裁决按钮，被覆盖的一侧同样先整份备份。真机验证中还发现并修掉一个缺口：已迁完但旧目录内容与 store 不同时，原实现会把它当成「没删干净的残留」，用户没有选边入口，现在按内容比对改判 `Hybrid`。
- 旧目录里有不属于我们的条目时只搬数据、保留目录（`Foreign`），面板说明原因并给显式清理入口；`layout.json` 版本高于本程序时所有项目命令直接报错。
- `ProjectPaths` 收敛全部落点，并钉住三条安全不变量：ID 安全、真源必须在 `store/local/projects` 之下、旧目录与 store 互不包含。`skill_source` 的项目 staging 也因此回到 store 卷，与全局共用同一套实现。

**代价（如实记录）**：台账不再跟随项目 git。换机器需要重新添加项目并导出/导入 store 数据；协作方之间只共享渲染出来的 agent 目录，不再共享 targets 与来源记录。

## 项目级矩阵按 agent 展开

- 列头与全局面板一致：只显示 agent 图标 + 计数，不再写文字目录名；一个 agent 一列。
- 共享同一物理目录的 agent（Qoder / Qoder CN → `.qoder/skills`，Codex / Gemini / Pi → `.agents/skills`）两列状态恒定相同，点哪一列改的都是同一个 target，`aria-label` 与悬停说明写明了这层共享关系。
- 未实测落点是与全局一致的虚线方块占位，不再是「待实测」文字。
- 能力闸收紧为「启用且 Skill 能力成立」的 agent 才出列，档位为 OFF 的 agent 不会再造出一个永远没有列的目录。

## 启动主题不再跳变

系统浅色、应用设置深色时，打开客户端会先看到浅色再闪一下变深。根因是主题真源在 `settings.json`、只能异步读，而 `index.html` 的预帧脚本只看系统偏好。现在把用户选择镜像到 `ccswitchx.theme`，预帧脚本优先读它，`useLayoutEffect` 负责翻 class 并刷新镜像；真源仍是设置文件，跨窗口或改存储根后会被纠正回来。

真机验证条件正是原 bug 现场：系统浅色 + 设置深色，导航提交帧与冷启动后的首帧 class 都已经是 `dark`。

## skills.sh 趋势改为点「趋势」才请求

原先切到 skills.sh 页签就抓一次趋势榜，多数人只是想搜索，白等一次网络。趋势独立成第三个页签、点击驱动请求；skills.sh 页签未搜索时显示「输入关键词搜索」空态，不再拿榜单兜底；趋势页签隐藏搜索框，分页与重试仍走「加载更多」。

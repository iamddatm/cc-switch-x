# CC Switch X v0.15.0

这一版把云端备份从「到点就无脑覆盖」改成「有变化才上传」，云端副本和本地历史都只记录真实的改动。

## 内容有变化才上传覆盖

- 自动快照与自动上传各自独立判定内容指纹：指纹由排序后的「相对路径 + 文件 sha256」再取一次 sha256 得到，不含打包时间与应用版本，因此升级应用本身不会触发一次多余备份。
- 与最新一份快照同内容时不再新建自动快照：等内容不会挤掉「保留份数」窗口里真正有内容的历史，裁剪只在确实新建快照时执行。
- 上传基线改为「云端那份包当前的内容指纹」，记在 `state/cloud-backup.json`。因此两种情况仍会补传：手动「立即备份」过的内容（云端还没有它），以及上次上传失败的内容（不必再等满一个间隔）。
- 从云端恢复成功后会把下载包的指纹写入基线，换机恢复完不会立刻把同样的内容原样传回去。
- 状态文件丢失或损坏按「未知」处理，退化成多传一次覆盖，不会丢数据。

## 保持不变的部分

- 手动「立即备份」「立即上传」「从云端恢复」仍是无条件执行，不受指纹闸影响。
- Git 自动同步本来就是变化驱动（工作区干净不提交），它与 WebDAV 的互斥关系、间隔为 0 即关闭、保留份数语义都未改动；云端 manifest 契约与前后端类型也没变。
- 备份面板文案改为「内容有变化才会打包上传覆盖」，并说明内容未变化时不产生重复快照。
- 代价：内容长期不变时到期判定会持续成立，后台线程每小时多跑一次真源读取与哈希。这与原本每小时解析一遍快照清单同量级，且在后台线程、维护锁之外执行，不阻塞界面。

## 验证

- `cargo test` 563 通过 + 集成测试 5 通过，无告警。新增 11 个用例覆盖：指纹只覆盖可移植真源（改 `local/`、`state/`、密钥、日志不改指纹）、同内容的两份快照指纹相同、内容未变时云端 PUT 请求数不再增加、上传失败后下一轮补传、手动快照会被补传、旧状态文件缺字段读成未知。原有 4 条 `periodic_once_*` 与 `auto_upload_failure_is_recorded` 未放宽断言、原样通过。
- `pnpm test` 212 通过（26 个文件）；`pnpm build`（含 `tsc -b`）与 `cargo check` 通过。
- **未覆盖**：未接真实 WebDAV 服务端与真机 UI 验证，上传去重仅由测试内的假服务端请求计数证明；多台设备同时开启自动上传时仍是「本机最新快照覆盖云端」，本版未引入设备间协调。

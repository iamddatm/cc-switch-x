# CC Switch X v0.17.0

这一版让用户级 Skills 能发现并接管「不是我们落的」那些副本，云备份则改成「变更即上传」，并给云端恢复补上续传、交叉校验与下载进度。

## Skills：发现未纳管，导入并接管

对齐上游 cc-switch 的「未纳管 Skills」，但纳管集合按我们的文本真源算，不依赖任何库表。

- Skills 页多一个 **「未纳管」** 页签（带条数），进面板时自动扫一次并在列表上方给一条提醒横幅；没扫出东西就不出现，也不需要用户先点某个按钮才知道有漏管。
- **扫描根**：注册表里每个有 `skills_dir` 落点的 agent（各自解析过 `baseOverride`），外加跨工具约定的 `~/.agents/skills`。只卡 `supported`（有没有这个落点），不卡 `switchable` —— 只读发现不受能力闸限制，写盘侧照旧卡。真源目录本身不当扫描根。
- **归属判定**沿用既对口径：链接（symlink 或 Windows junction）指向真源目录下，或 copy 部署留下的 `.ccswitchx` 指向仍然存在的真源条目 —— 两者都不是才算外来。所以我们自己 junction 部署的那份不会被误当成未纳管。
- **候选判定**：一层目录、非点开头、含 `SKILL.md`；按目录名跨根合并成一条并记 `found_in`；同名而内容不同只报警告、只导入先发现的那份；不是候选的（散文件、缺 `SKILL.md`、目录名推不出合法 ID）逐条点名，不静默丢。
- **冲突单独分区**：`slug(目录名)` 命中真源已有 ID、但盘上这份不是我们落的，只允许「另存为新 ID」，**永不接管**（要删的那份内容并不在真源里）。
- **接管**按用户勾选把外来目录换成指向真源的部署：真目录必须先证明真源保存的是同一份（目录指纹一致）并整份留底到 `backups/skills/<毫秒>_adopt_<agent>_<目录>` 才允许删；链接**只解链**，绝不递归删（Windows 上对 junction 递归会一路删进真身）。替换后交回 `set_enabled` 落启用矩阵，启用失败就把原样还回去。只勾「收进真源」不勾 agent，则不改盘。
- 未纳管信息只在扫描时现算，不写 `index.db`、不落任何文件。

## 云备份：变更即自动上传

- 拆成两个独立开关：`cloud.enabled`（通道启用，参与顶部「远端备份方式」单选，与 Git 自动同步互斥）与 `cloud.auto_upload`（自动上传）。自动上传必须先启用通道，关闭通道会一并关掉自动上传；通道开着、自动备份关着 = 只手动上传。旧的只含 `autoUpload` 的设置文件读进来时，开过自动上传的视为通道已启用，升级后不会静默失效。
- 真源写入后（`store` 的写/删、Skill 目录落盘、`agents/<id>.json` 矩阵）向 `change_signal` 打点，工作线程 **1 秒防抖、持续写入最多合并 10 秒**，然后打包**当前真源**直接上传，不新建本地快照（快照仍由「立即备份 / 自动快照间隔」管）。
- 先算内容指纹，与 `state/cloud-backup.json` 里「云端那份包当前的指纹」一致就跳过。基线独立于是否新建了快照，所以手动「立即备份」过的内容、以及上次上传失败的内容都能被补传。
- `periodic_once` 每小时仍补一次，覆盖关闭应用期间的改动；快照间隔为 0 时也能补传。
- 从快照恢复（含云端恢复）期间用 `SuppressionGuard` 抑制自动上传，避免「恢复」这个动作反向把云端盖回去。
- UI：区块内的「自动备份」复选框切换即保存（策略不与连接草稿混在一起），通道未启用时禁用。

## 云端恢复：续传、校验与进度

- 超时拆成两类：控制类请求（PROPFIND / HEAD / MKCOL / MOVE / DELETE / 读 manifest）**30 秒上限**，一个卡死的控制请求不会再拖住整条串行队列和界面；传输类 **300 秒起步，再按 16 KiB/s 的保底带宽随包大小增长**，慢网下换机恢复大包不会被固定总时长截断。
- 下载支持 **Range 续传**，同一次恢复最多 3 次尝试；用尽后把最后一次错误报给用户，并且**丢弃半包**，不在盘上留残余文件。
- 下载边写边算整包 sha256，并与 manifest 声明的包大小、文件数量交叉校验，不符直接拒绝恢复。
- 恢复期间后端每 256 KiB 推一次 `cloud-restore-progress`（已下载 / 总字节，未知总量为 0），确认框里能看到进度；打开确认框会先刷新一次远端状态，不再拿可能已过期的旧包信息去确认覆盖。

## 顺带修的既有缺陷

- junction 建链走 `cmd /c mklink /J`，而 `expand_root` 会保留声明里的 `/`：Windows API 能吃这种混用分隔符，`cmd` 却判它「无效参数」。结果是符号链接不可用的机器上永远只能降级成 copy 部署。现在统一按 `cmd` 要求的反斜杠形态传参，并有回归测试钉住。
- 链接判定收拢成 `adapters::skills::is_link` 单点（`symlink_metadata` + `read_link` 双保险），项目级扫描共用同一份 —— Windows 上 `DirEntry::file_type()` 认不出 junction，不该再各写一份判定。
- 导入 / 安装 Skill 时清除目录里别人留下的 `.ccswitchx` 标记，不再混进真源。

# CC Switch X v0.19.0

这一版把 v0.18.0 只能「报出来」的 Skill 落点差异做成可以一次处置的动作。上一版真机跑完，用户机器上实测 24 条勾选与落点不符（多为与 cc-switch 并存后落点被删或被对侧接走），逐条走「取消勾选 → 重新勾选」根本点不动。

## 一键处理：三种差异各自的处置

- 新增 `services::skill_repair` 与 IPC `repair_skill_deployments`：**先自己重跑一遍 `skill_verify::verify` 再处置**，前端传来的清单一概不信 —— 落点路径要按注册表 + `baseOverride` 现算，用户点确认之前可能又在对侧工具里动过一轮（与 `install_discovered_skill` 同一口径）。逐条独立成败，一项失败不影响其它项。
- `missing`（落点空）→ 重新部署，交回 `skill_source::set_enabled`：能力闸、检测门禁、矩阵写入都沿用它，不另立第二套口径。
- `foreign`（落点被别的工具接走）→ 交回 `skill_takeover::take_over_one`（本版把它提为 `pub(crate)`），**不新写第二套接管逻辑**。
- `sourceGone`（真源已删，只剩悬空勾选）→ 退账清矩阵，盘上一个字节不动。其中拼不出真源路径的非法 ID 直接走 `update_matrix`：`skills::remove` 在 `entry_path` 那一步就会失败，不绕开这条，这个勾选就既启不了也关不掉。

## 「抢回」不等于无脑覆盖：安全边界一处没放宽

- 落点是**链接**时只解链再换成我们的。Windows 上对 junction 递归 `remove_dir_all` 会一路删进链接的真身，所以绝不整目录删 —— 真机验证里对侧目录与其正文逐字节不变。
- 落点是**我们从未部署过的普通目录**时，必须先证明它与真源同目录指纹、再整份留底到 `backups/skills/`，才允许替换；内容对不上就原样保留并在报告里说明原因。这一档仍然要人工裁决，工具不替用户猜。
- 所以 v0.18.0 那句「只报告，绝不动盘」现在限定为**核对**（`verify_skill_deployments`）；动盘的只有 `repair_skill_deployments` 这一条路，且必须由用户点确认。命令挂在 Skill 写任务互斥锁与 maintenance 读锁下，之后 `rebuild_index` + `notify_git`。

## 接入位置

- `SkillDeploymentNotice` 加「一键处理」。横幅文案从「教用户怎么手动恢复」改成「说清这个按钮会做什么」，细节移到确认框，横幅只留一句「抢不回来的原样保留并逐条说明原因」。
- 确认框按档列出将要动什么（重刷 N / 抢回 M / 退账 K），并提示「对侧工具之后可能因此报它自己的漂移」；**确认框本身不写盘**，清单以点下去那一刻的磁盘为准。
- 处理结果分档播报（重刷落点 / 抢回落点 / 本来一致 / 取消勾选 / 未处理），`refused` 逐条给原因 —— 它是「按纪律没动它」，不是执行出错。
- `useDrift` 加 `repair()`：处置完重扫并广播，横幅与顶部状态条的计数跟着同步，不会停在处理前的数字上。它与 `resolve()` 的区别是失败会往外抛，避免面板把失败播报成「没有差异」。

## 未做

- 不做自动监听、不做启动时自动处理：动盘必须有人点。
- 反向核对（盘上还挂着我们部署的链接、矩阵却已取消勾选）本次仍不报。
- Rules / Subagents 取消勾选遇到外来文件的同类死路仍未改，处置纪律要单独定夺。
- 抢回之后不通知对侧工具，它的台账会失配 —— 目前只在确认框里提示，不做跨工具协调。

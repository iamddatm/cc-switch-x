# CC Switch X v0.6.1

本版本只做一件事：把 v0.6.0 里被能力闸挡住的项目级 Skills 同步**放开可用部分**。v0.6.0 的三个项目级落点都还没做过真机验证，所以矩阵整屏「待实测」、勾选与同步都不可用；现在其中两个已按真机证据升档。

## 能力闸升档（真机证据）

- `.claude/skills` → Claude Code：在真实项目里放入探针 skill 后 `claude -p` 会报出该 skill 名，移走后同一问句回答 `NONE`（正/负对照各一次）。
- `.qoder/skills` → Qoder CN：`qoderclicn skills list` 在项目目录下直接报出 `.qoder\skills\<探针>\SKILL.md` 的路径。
- `.agents/skills`（Codex / Gemini / Pi）：**仍为待实测**，保持不可勾选。这台机器上 codex CLI 没有 skills 概念、gemini 未安装、pi 因缺少凭据无法启动，取不到「agent 真的读了这个目录」的证据就不升档（能力闸规则见 `AGENTS.md` 与设计文档 §6）。
- 判定分两层，缺一即挡：目录本身已实测 **且** 映射到该目录、当前在设置里启用的每个 agent 都已实测过 skill 落点。例如同时启用 `qoder`（国际版，用户级 skill 未实测）与 `qoder-cn` 时，`.qoder/skills` 这一列依旧不可勾选。

## 实际可用的路径

- 项目里为 Claude 写的 skill，勾选 `.qoder/skills` 后点「立即同步」（或开着自动同步进入项目）即可复制到 `.qoder/skills/`；反向、以及「只改了 Claude 侧就同步到 Qoder 侧」的更新与删除传播同样可用。
- 矩阵中 `.agents/skills` 列显示「待实测」，不提供开关；「立即同步」只在至少有一个可勾选目录时才启用。

## 验证

- 新增真机端到端测试 `src-tauri/tests/project_skills_real_project.rs`（默认忽略，`cargo test -- --ignored` 运行）：以本仓库为真实项目、临时 store 为数据目录，串起注册 → 基线 → 能力闸 → 勾选 → 同步复制 → 幂等（不重复写盘、不重写项目 JSON）→ 删除传播并留备份 → 移除条目，结束后自动清场。
- 新增能力闸单元测试：未取证目录不得出现在可勾选列表；共享目录只要有一个启用的 agent 未实测就整体挡下。

# CC Switch X v0.21.0

v0.20.0 的 WebDAV 云备份只有「自动上传」，而且是一改动就 1 秒防抖上传；从机器拿不到云端更新，进面板点「从云端恢复」还得先等一次联网探测（还要抢 `cloud_ops` 锁），网络慢或后台正在传 14 MB 包时按钮长时间置灰。这一版按「一台主工作机 + 多台从机器」的使用方式，把自动上传、自动下载拆成两个独立开关，并把面板改成缓存优先。

## 两个开关，一个通道闸

- 「自动上传」与「自动下载」互不绑定，但都必须先启用 WebDAV 通道；关通道会一并停掉自动任务。主机器只开上传，从机器只开下载，与 Git 区的「自动提交 / 自动拉取」是同一套心智。
- **自动上传不再无限防抖**：新增「上传延迟」，可选 1 / 6 / 12 / 24 小时，默认 1 小时。改动停下满延迟才传；持续编辑时首处改动后最多等 `min(4 × 延迟, 24h)` 兜底补传，避免写一整天却一次都不传。内容指纹与上次上传一致则跳过，不产生重复传输。
- **自动下载以云端为准**：启动时检查一次，之后每 15 分钟一次；先 `PROPFIND` 读元数据，ETag 或「修改时间 + 大小」判定没变就停住，不读 manifest、不下载。变了才读 manifest，包 sha256 与基线一致或 `contentFingerprint` 与本地真源一致都只更新基线、不恢复。编辑机开着自动上传且本地还有未上传改动时跳过本轮，让上传先把本机内容落定；纯下载机不受此限，云端更新照样覆盖本地。
- 自动下载复用现有恢复流水线：`maintenance` 写锁、自动建 `PreRestore` 安全快照、重建索引，期间 `SuppressionGuard` 抑制自动上传。下载包只作临时恢复源，成功后不留 `cloud_restore_*` 可见快照，并按当前保留数 `prune` 掉超额快照，避免每次云端更新都多一份快照。
- 上传与下载共用 `cloud_ops` 串行；上传进行中到下载检查点，本轮直接顺延，不排队抢锁。

## 一个 worker，三个定时器

- 原来的 `spawn_change_worker` 扩成「延迟上传 + 定期下载 + 定期对账」的单线程循环，共用一个 `recv_timeout`，没有改动时阻塞到最近的定时点，不额外开线程。`pending` 只存在内存里，应用重启后由启动对账重新计时。
- 上传触发不再依赖 `periodic_once`，改为三个入口：变更信号、每 15 分钟对账、设置保存后的唤醒。这样启动前遗留的未同步内容、上次失败、恢复被抑制但内容已变、刚打开自动上传都能被补捞。
- 普通失败 5 分钟后重试并重置计时，避免网络抖动时每个 tick 都重新打包上传；连接不完整不是故障，静默保留 pending 等用户补齐。
- 成功上传/恢复后发 `cloud-auto-synced` 事件，载荷带动作类型、上传字节数，或恢复文件数、删除数与安全快照名；备份面板收到后整面板刷新，新快照与清理结果同步出现。

## manifest 升到 schema 2

- 云端 manifest 升到 **schema 2**，新增必填字段 `contentFingerprint`（上传归档本身的真源内容指纹）。schema 1、缺失 manifest、格式不符统一按「不兼容，请从源设备重新上传」拒绝，旧版裸包兼容分支与面板提示一并删除。
- 指纹取的是**正在上传的那份归档**，不是记录时重读真源——否则上传期间真源再变，会记下一份与云端包对不上的基线，之后永远误判「已同步」。
- 升级后主机器需要手动「立即上传」一次，把云端换成 schema 2，从机器才能自动下载。旧设置文件不做语义迁移，升级后请到面板确认一次通道与两个自动开关。

## 认证失败就停手

- WebDAV 的 401/403 归为新的 `AppError::CloudAuth`，与普通网络错误分开。自动任务遇到认证失败写 `auth_paused_until = 现在 + 1 小时`，暂停期内不发任何自动请求，避免反复重试触发坚果云更久的临时封禁。
- 手动上传、手动恢复、测试连接、刷新云状态不受暂停影响；任何一次成功的实时探测或手动操作都会清除暂停。

## 面板：缓存先渲染，恢复按钮只认已知事实

- 运行状态文件拆成两组字段：`synced_*` 是同步基线，只在上传/恢复成功后写；`observed_*` 是观测缓存，实时探测与自动探测都可写。**实时探测绝不写 `synced_*`**，否则用户打开一次面板，worker 就会误以为云端已同步、永远不下载。
- 新增 `get_cloud_status_cached()`：只读本地设置、密钥与运行状态文件，不联网、不抢 `cloud_ops`，立即返回上次已知状态。面板先渲染缓存，再在后台联网刷新，刷新期间保留旧状态不清空。
- 「从云端恢复」只在已知事实成立时置灰：远端明确没有包、manifest 明确不兼容、连接未配置、表单有未保存改动或任务进行中。状态未知（首次运行、缓存为空）时可点，由恢复命令自行校验并报错。
- 状态区新增「上次下载」「本机本月上传」，下载失败时显示「上次自动下载失败：…」；面板头在联网探测时显示「检查中…」，不阻塞按钮。
- 连接参数（地址、账号、远端目录、密码）任一变化或清空地址，都会删除 `state/cloud-backup.json`，同步基线与观测缓存全部作废；只切开关或改延迟不动基线。新增连接代次：换连接前启动的旧任务跑完后不再回写新连接的运行状态；等锁后会重读运行状态，避免拿锁前旧快照覆盖刚完成的同步基线。

## 验证

- `cargo test`：**666 lib + 3(`asset_chain_e2e`) + 2(`sessions_e2e`) 通过**（v0.20.0 是 632 lib，新增 34 条），`cargo check` 无告警。
- 新增用例覆盖：自动下载关闭/通道关闭不发请求；元数据未变只有一次 `PROPFIND`；sha 未变只读 manifest 不下载；纯下载机本地被改仍以云端为准；编辑机有未上传改动时跳过；schema 1 / 缺失 manifest / 缺 `contentFingerprint` 三路拒绝且本地字节不变；下载后 `synced_*` 正确落盘；自动下载按 `retain_count` 清理快照；实时探测不改变 `synced_*`；认证失败暂停后自动 tick 零请求、手动探测成功清除；连接代次阻止旧任务回写；上传延迟按最后一次改动计、持续编辑走兜底上限；对账只在本地与基线不一致时建 pending；上传失败 5 分钟后重试；本月上传字节按月重置。
- `pnpm test`：**252 通过**（27 个文件，v0.20.0 是 244）。新增 8 条覆盖两个开关独立读写、上传延迟、缓存先渲染且实时探测未返回时恢复按钮仍可点、自动同步事件触发刷新、manifest 缺失/不兼容的置灰与文案、上次自动下载失败展示。
- `pnpm build`（含 `tsc -b`）与 `node scripts/check-release-version.mjs` 通过（v0.21.0）。
- **本版未做真实 WebDAV 双机往返**。所有网络行为由测试内的假 WebDAV 服务驱动，ETag 取值、分页、限流与 14 MB 整包在坚果云免费版上的实际表现都没有实测；上线后需要在主/从两台机器上跑一次完整往返再宣告稳定。

## 未做

- 不做文件级增量同步：首次/换机上千个文件半小时内会撞坚果云 600 次请求限制，整包方案请求数恒定。代价是从机器最多滞后一个上传周期。
- 不做云端多版本历史、合并与冲突选择；自动下载以云端为准，冲突出口是本机 `PreRestore` 安全快照。
- 不做上传配额自动暂停，只展示本机本月上传量，由用户调延迟。
- 不把 `local/`、`state/`、`secrets.local.json` 纳入同步包，沿用现有快照范围。

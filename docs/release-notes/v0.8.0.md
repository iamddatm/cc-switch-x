# CC Switch X v0.8.0

项目级 Skills 换模型：从「几个 agent 目录互为副本」改成「项目里只有一份真源，其余目录是渲染产物」，并把项目面板补齐到与全局面板同等能力。设计口径见 `docs/superpowers/specs/2026-10-26-project-level-skills-design.md`（§4 方案 B）。

## 真源搬进项目

- `<project>/.ccswitchx/skills/<id>/` 是唯一可编辑真源；`.claude/skills`、`.qoder/skills`、`.agents/skills` 只是渲染产物，可随时删除重生成。台账 `.ccswitchx/skills.json` 升到 version 2，记 `targets` / `canonical` / `dirs` 渲染基线 / `source` 来源，随仓库提交且不含绝对路径。
- 安装、导入、新建**只落项目真源，不带渲染目标**：往仓库里的 agent 目录写文件，必须由「勾选 + 立即同步」这一步显式发生。
- 项目真源不写 `.meta.json` 也不放任何归属标记文件；写入只复制，不做 symlink / junction。
- 取消勾选只写回 `targets`、保留文件（该副本从此按未跟踪处理）；只有「移除该目录副本」和「卸载」才删文件；真源与所有 target 都消失才移除台账条目。

## v1 → v2 迁移

- 旧台账项目首次打开时给只读预览：列出将在你仓库里新建哪些文件、哪些条目目标不一致，确认后才 apply。
- 迁移**只新建文件，不改动任何已有 agent 目录的字节**；`targets` 不一致时整体拒写，冲突未裁决不动盘；旧 JSON 先备份、写完回读校验、失败回滚新建的目录。
- 新项目直接写 v2：`targets` 空、`canonical` absent，不复制任何内容。

## 同步引擎按真源渲染

- 格子六态且写成文字：`已同步` / `无` / `待更新`（真源变了，同步可安全覆盖）/ `已改`（这份副本被外部改过，必须人工裁决）/ `未跟踪` / `不可用`；未实测的目录只显示`待实测`、不给开关。
- `edited` 与 `untracked` 永不自动覆盖或删除；自动同步只处理无歧义情况、**永不产 purge**；真源消失（`canonicalMissing`）只能由显式 purge 处置。
- 多于一个目标被外部改动、或目标与真源都不等于基线，一律视为冲突、不自动写盘，弹对比让用户选「以某侧为准」（胜出方先 `adopt` 回真源，再渲染其余）或「两边都保留」（落败方另存 `<id>-copy`，重名递增，不进 `targets`）。
- 自动同步默认开启、按项目可关，触发点是切换到该项目 / 项目内手动刷新 / 启动恢复上次项目，不驻留文件监听；手动同步始终可用。

## 面板与全局面板对齐

- 项目面板补齐：已安装 / 发现两个 tab、市场安装与来源预览下载解压、检查更新与更新、批量部署与取消部署、行菜单（查看详情 / 编辑正文 / 收进真源 / 移除副本 / 卸载）、搜索与筛选、三档空状态。
- 搜索、来源、目录、状态、仓库筛选抽成纯函数 `skillFilters`，作用域差异收敛进 `skillScope` 适配器，两个面板共用同一套判定；`SkillsPanel.test.tsx` 一行未改仍然全绿，那是这次抽取的回归证明。
- 复用停在行组件这一层，没有再往上抽格子：全局那颗圆点只表达「开 / 关」两态，而六态里的「已改（要人工裁决）」压成一种颜色最容易误导人，所以项目格子仍占同一列宽、里面放状态文字加悬停说明。
- 检查更新的结果只写本机 `local/project-skill-checks/<projectId>.json`，绝不进随仓库提交的 `skills.json`；更新只换真源，渲染留给下一次同步（目标会短暂显示 `待更新`）。
- 项目根拒绝 home、store root 与用户级 agent 配置根之内的路径；「从 cc-switch 导入」仍只在全局提供。

## 能力档位

- `.claude/skills` 与 `.qoder/skills` 有真机读取证据，可选为渲染目标；`.agents/skills`（Codex / Gemini / Pi）**继续 `verified: false`**，本机取不到证就不升档，测试全绿不算证据。
- 判定仍是两层缺一即挡：目录本身已实测，且映射到该目录、当前在设置里启用的每个 agent 都已实测 skill 落点。

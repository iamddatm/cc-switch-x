# CC Switch X v0.11.1

修一个坚果云上的上传误判：包已经完整传完，客户端回读校验大小却报「大小不一致」，把成功当失败。

## 坚果云 HEAD 返回 0 导致上传误判

- 根因：坚果云对 `HEAD` 一律回 `Content-Length: 0`（对象有 13 MB 也一样）。v0.11.0 上传后靠 HEAD 回读大小做校验，于是每个包都被判成大小不一致，上传整体失败。
- 读对象元数据改为**先 PROPFIND、再退 HEAD**：`Depth: 0` 且只请求 `getcontentlength` / `getlastmodified` / `getetag` 三个属性，大小以 `getcontentlength` 为准（这才是 WebDAV 规定的元数据来源）。
- 回退条件收紧：只有服务器明确不支持（`405` / `501`）或应答里一个已知属性都解析不出来时才退回 HEAD。`404` / `409` 视为对象不存在（延续坚果云 404→409 的处理），`401` / `403` 报鉴权错误，`200` / `207` 都按 multistatus 解析。
- 应答读取上限 64 KiB，超长截断后按解析失败回退 HEAD；解析器按本地名匹配元素，兼容 `d:` / `D:` / `lp1:` 等命名空间前缀，不引入 XML 依赖，也不影响 `head()` 与 manifest 回读。

## 验证

- `cargo test` 550 通过 0 失败，新增 5 条：HEAD 恒为 0 时上传成功且 `head()` 读到真实大小、服务器不支持 PROPFIND 时仍能发现截断上传、坚果云真实 `Depth: 0` 应答解析、其他命名空间前缀、无已知属性时回退 HEAD。
- `pnpm test` 210 通过（26 个文件）；`pnpm build` 通过。
- `node scripts/check-release-version.mjs v0.11.1` 通过。

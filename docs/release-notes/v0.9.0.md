# CC Switch X v0.9.0

上一版把项目级 Skills 的真源搬进仓库，这一版处理随之暴露的两件事：漂移在 UI 上「报得出、处置不了」，以及面板重复代码已经多到同一个 bug 要修几遍。发版内容是**打通漂移处置闭环 + 前端按职责去重**，用户能看到的只有前者，后者是行为不变的重构。

## 漂移处置闭环（真机验证过）

- `DriftBanner` 补上「重新检查」按钮 —— `useDrift().rescan` 早就写好了，但全仓零调用方，注释承诺的处置动作在组件里并不存在，「启动与手动 rescan 只报告」这条纪律在 UI 上落不了地。
- Prompts 面板接入漂移横幅：后端本来就会对 prompt 判漂移并在启用时阻断（`drift.rs` 的 `ensure_no_open_drift_for_agent`），但面板不显示，用户只能读到一串原始错误文本、无处处置。现在被 `DriftUnresolved` 挡住时立刻重扫，横幅与「采纳磁盘 / 重刷真源」两个按钮当场出现。
- 新增全局漂移状态条：横幅只在有漂移时渲染，「外部改了文件但不重启」就永远发现不了；`rescan_drift` 本来就是跨 agent 全量的，所以只给一处常驻入口，它与各面板横幅共用同一份结果（`DRIFT_RESCAN_EVENT`），不会出现两处数字各说各话。
- Subagents 面板补渲染 `drift.error`：此前重扫失败是静默的，用户以为「一致」。
- 状态条改为直接吃 `useDrift`，不再自己抄一份订阅；并补 `loading` —— 首轮清单到手前不能显示「一致」，否则启动瞬间会先闪一个错误的绿灯。

## 扫描计数与失败上报

- 修掉「逐 agent 覆盖同一个 state、最后一个被当成总数」的计数错误：跨 agent 结果改为求和。
- 扫描失败改由独立的 `scanError` 报出。原先写进 `formError`，而它只在选中资产时渲染，等于看不见。
- 只扫 `detected && supported` 的 agent，目标口径与格子列一致（复用 `supportedAgents`）。

## 入口与文案

- Skills 两版面板的「检查更新」改为常驻：原先 `updatesCount > 0` 时它会被「全部更新（N）」整个顶掉，想重检只剩 ⋯ 菜单里一个不同名的入口；现在两者并存，菜单里那条重复入口删掉。
- 删掉 Git 备份区那个只有 `title`、没有可访问名的裸图标按钮：它调的是全面板 `refresh()`，坐在 Git 标题行里却会被读成「只刷 Git」。云备份区那颗有合规名称且语义独立，保留。
- 快照保留数旁的说明原文写「清理只作用于 snapshots 目录」，而同面板的「清理写入备份 / 清理日志」清的是另外两处，两个「清理」撞词且指向不同；改成「保留数只裁剪 snapshots 目录里的旧快照，不动写入留底与日志」。

## 前端按职责去重（行为不变）

- 整文件资产三面板：Rules / Subagents / Hooks 的容器、左栏、右栏壳逐行相同，抽到 `components/assets/AssetEditor.tsx`；编辑状态机（选中 → 读真源 → 新建 / 保存 / 删除）抽到 `useFileAssetEditor`，面板只留表单形状与 parse / render；右栏顶部漂移横幅抽到 `AssetDriftHeader`。Hooks 没有扫描与漂移，靠不传对应 prop 表达。
- Skills 两版面板：搜索 / 来源 / 仓库三轴与行勾选收进 `useSkillFilters`，「已安装 / 发现」tab 与仓库多选气泡抽成 `SkillViewTabs` / `SkillRepoFilter`，检查报告的失败行收进 `skillFilters.checkFailureLines`；面板只保留自己那第四轴（启用状态 / 部署目录 + 状态）。
- 备份面板：1243 行的单文件按块拆出 `GitSection` / `CloudSection`（容器先降到 838 行），纯搬家 —— DOM、文案、`disabled` 条件一字未改；再把输入草稿下沉到各分区自己管（容器 779 行，两块各 294 / 258 行），容器只收最终 draft 负责落库，「空地址 = 清除远端」「密码留空 = 保持不变」这两处翻译回到发生它的那一块。
- 筛选链补 `useMemo`：原先每敲一个搜索字符都要全表扫一遍谓词，还会连带把依赖 `selectedRows` 的 `enabledTargets` 挤出缓存。
- `.gitignore` 的 `local/` `backups/` `logs/` `state/` 四条是无位置限定的兜底，实际连仓库里任何层级的同名目录一起忽略：新建的 `src/components/backups/` 直接 `add` 不进来，**且 git 不报错**。补 `!src/**/{local,backups,logs,state}/` 放行（后匹配的规则赢，顺序不能颠倒），store 兜底没有削弱。

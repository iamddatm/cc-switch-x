# CC Switch X v0.11.0

这一版全部围绕云备份：给远端补了 `manifest.json` 描述文件，修掉坚果云上「新包传完、改名失败」的覆盖上传问题，并把备份面板里最常用的 WebDAV 区提到最前面。另有一处面板级提示的通用修法和一处设置文件容错。

## 云备份上传 manifest.json

- 远端目录从「一个 zip」变成「zip + manifest.json」：上传时先落包、**最后写 manifest**，manifest 里记 `format` / `schema` / 应用版本 / 设备名 / 上传时间 / 包内文件数 / 包的 SHA-256 与大小。写法对齐 cc-switch 的同步协议（产物在前、manifest 在后），但我们只有一个备份包，所以描述的是单个 `archive` 而不是产物映射。
- 恢复前先用 manifest 过三道闸：格式标识、协议 schema（高于本机直接拒绝并提示升级）、目标文件名；都通过才下载。下载后重算 SHA-256 与 manifest 比对，不一致说明传了一半或被人替换，直接报错并提示在源设备重传，不碰本地数据。
- 旧版上传的裸包（没有 manifest）照常能恢复，界面上给一条「来源与完整性无法核对，重新上传一次即可补齐」的说明。
- 「云备份」区新增「上传来源」：显示 `<设备名> · v<版本>`，悬停可看文件数与上传时间；manifest 版本不兼容时红色告警，解析失败时黄色告警。

## 坚果云兼容

- **MOVE 409**：我们原本用「临时对象 + MOVE 原子覆盖」上传。坚果云拒绝覆盖式 MOVE（目标已存在即返回 409），而代码只对 405/501 做回退，导致「新包已经传完，只差改名」被当成失败。现在 `405 | 409 | 501` 一律退回直写最终对象；直写也失败时错误里同时带上 MOVE 状态与直写原因。
- **GET 409**：坚果云在对象不存在时用 409 代替标准 404。manifest 探测把 `404 | 409` 都当「没有 manifest」，不再把旧包误判成读取失败。

## 备份面板：WebDAV 置顶

- 页面顺序改为「远端备份方式 → 云备份（WebDAV）→ 快照 → 占用空间 → Git 备份」。WebDAV 是日常主用通道，打开面板不用滚就能测试连接、保存、上传、恢复；那条一行式的「远端备份方式」单选留在最顶，因为它是 Git / WebDAV 的总开关。

## 动作反馈固定在滚动区之外

- 新增 `FeedbackBar`：动作结果（错误 / 成功）固定渲染在滚动区**之外**，列表滚到哪都看得见。此前提示写在滚动内容顶部，在页底的操作（WebDAV 测试连接、Git 验证远端、快照增删改、Skills 行内启用等）失败时提示会被滚出视野。
- 应用到备份、MCP、提示词、Skills、项目 Skills、Agents、Settings 七个面板；漂移、检查报告、迁移提示这类状态类信息仍留在内容里，避免把一屏占满。

## 设置文件容错

- `settings.json` 缺少 `storeRoot` 或 `theme`（被外部工具改坏、只留部分键）时回退默认值，不再让启动与设置保存整体失效；读出的补全结果可直接写回。
